# 도깨비 프롬프트 시험기

입출력 계약을 확정하기 전에, 실제 모델이 도깨비 반응을 쓸 만하게 만드는지 PC에서 확인하는 스크립트다.
장면마다 프롬프트를 만들어 로컬 모델(LM Studio)에 넣고, 자동 검사 결과를 CSV로 저장한다.
말투와 상황 반영 점수는 사람이 CSV에 직접 매긴다. Python 3.10 이상, 표준 라이브러리만 쓴다.

장면과 행동은 [터치 상호작용 기획안](../../docs/npc-touch-interaction-design.pdf)을 따른다.

- 주인이 NPC를 탭하면 포커스 줌 뒤 짧게 인사하고, 선택지(안부 묻기 · 관리하기 · 이야기 듣기)로 교류한다. 주인은 NPC를 끌어당겨 옮길 수도 있다.
- 손님은 도깨비를 건드릴 수 없고 전시관(건물·도깨비 배치)을 관람만 한다. 손님이 보는 동안 도깨비는 짧은 말풍선을 띄운 채 걸어 다닌다.
- 주인은 언제든 관리(재플레이)할 수 있어서 "조건 미충족" 상황은 없다.
- 행동은 4개 애니메이션(Idle · Walking · Positive · Struggle) 중 하나로 표현한다.
  - Talk는 아트의 w자 입 모양을 살리기 어려워 뺐다. 말하는 행동은 Idle에 말풍선으로 표현한다.
  - Struggle(버둥거림)은 NPC를 끌어당길 때 쓴다.
  - Walking은 손님 관람 중 말풍선을 띄우고 걸을 때 쓴다.
  - Negative는 거절할 상황이 없어 뺐다. 불편함은 대사로 드러낸다.
- 놀람 · 수줍음 · 서운함 같은 세부 감정은 대사로 드러낸다.
- 지난 일은 저장된 이력이 있을 때만, 문화재 사실은 검수된 데이터(서버 시드의 `realStory`)로만 말한다.
- 대화의 목적은 플레이어가 상호작용을 통해 도깨비에게 **정이 들게 하는 것**이다. 무뚝뚝하거나 장난스러운 성격도 상대를 밀어내거나 깎아내리지 않는다. 욕설과 지나친 퉁명스러움은 공통 금칙어(`data/forbidden.json`)로 거른다.
- 도깨비마다 실화 이야기가 3개씩 있다(`personas.json` 의 `stories`). 이야기 듣기 때마다 게임이 돌려 가며 하나를 주어, 3개를 다 들려줄 때까지 같은 이야기를 반복하지 않는다.
- **이야기 듣기는 AI 로 만들지 않는다.** 2B 모델이 사실을 지어내거나 필요한 내용을 빼먹어서, 검수한 이야기 대사(`unity-npc-generator/Data/default_lines.json` 의 `stories`)를 차례로 쓴다. 이 시험기는 이야기 장면(S10 · S11 · S18 · S19 · S20)을 건너뛴다.

## 프롬프트 구성

C# 프롬프트 조립기(`unity-npc-generator/Runtime/PromptAssembler.cs`)가 이 구성과 글자 하나까지 같은 프롬프트를 만든다(`Verify` 가 비교한다).

- **시스템 메시지는 도깨비마다 고정이다.** 이름·출신, 성격, 감정 표현, 말투, 예시 대사, 공통 규칙 여덟 줄만 싣는다.
  - 18:46 시험(Kanana)에서 응답 중앙값이 5.3초로 늘었다. 첫 시도 통과가 29%라 평균 1.71번 만들었고, 규칙이 길어 입력 토큰이 약 800 → 1,040 개로 늘었다. 그래서 규칙은 뜻을 지키며 짧게 다시 썼고(규칙 780 → 494자), 말투 다짐을 대사 줄로 옮겼다. 행동 뜻을 대사로 읽어 "놀이처럼 신나서 버둥거려!"처럼 몸짓을 말해서, 행동 뜻(`actions.json` 의 `meaning`)도 몸짓 대신 '하는 말'로 쓰고 규칙에 '몸짓 설명은 넣지 않는다'를 넣었다.
  1. 애착 — 밀어내기·깎아내리기·평가하지 않기, **낮춰 부르거나 거만하게 말하지 않기**. 반말 도깨비가 "주인아"라고 불렀다. 낮춰 부르는 말은 늘어놓지 않고(오히려 쓴다) "주인아"·"손님아"는 공통 금칙어(`낮춰 부르기`)로 거른다. '주인님'·'손님'을 함께 적었더니 주인 장면에서 "손님께서"라고 해서 부르는 말은 적지 않는다(18:03 시험)
  2. 성격은 고르기와 말투에만, 세부 감정은 대사로
  3. 자료에 있는 것만. **지금이 낮인지 밤인지, 날씨도 자료에 없으면 말하지 않는다** — 게임이 접속 시각을 넘기지 않는데 예시의 "오늘 밤 순찰"을 옮겨 낮에도 '오늘 밤'이라고 했다
  4. **관리는 주인이 닦아 주는 일, 끌어당기기는 주인이 옮기는 일. 도깨비는 닦이고 옮겨지는 쪽**이고, **자기 몸과 기분은 남이 보듯 말하지 않고 느끼는 대로** — "닦을 수 있어서 고마워요", 끌려가며 "조심할게요", "개운해진 모습이 참 보기 좋네"라고 했다
  5. 한국어로만, **자기 이름을 말하지 않기**("반갑게요, 향산이"), 행동 이름 없이
  6. **말투에 적힌 어미로만 맺고 존댓말·반말을 섞지 않기**, 어미를 덧붙여 어색하게 만들지 않기("반갑게요", "반가워구먼")
  7. **고른 행동과 지금 상황에 꼭 맞는 말만, 짧은 문장 한두 개로 우리말 어순대로. 길이를 채우려고 말을 덧붙이거나 '~서'를 거듭 잇지 않기** — "이틀 전에 닦아 주셔서 선명해져서 고마워요", "부딪힐까 조마조마한 날개에 신경 쓰며, 손님께서 부드럽게 다뤄 주시면 좋겠어요"처럼 어색하거나 행동에 필요 없는 말을 붙였다
  8. 예시와 **아래 자료의 문장을 그대로 옮기지 않기**
  - 이름·어미·반복은 규칙만으로 지켜지지 않아 **출력 검사로 강제한다**(아래 "강제").
  - 기준 모델은 **Mi:dm 2.0 Mini** 다. 세 모델 비교(2026-11-11)에서 대사가 가장 짧고(문장자름 3%) 말투를 가장 잘 지켰다(어미일치 74%). Kanana 1.5 는 길게 써서 잘리고(문장자름 46%) 페르소나 칸을 그대로 옮겼고, EXAONE 4.0 1.2B 는 영어를 섞고 상황과 동떨어진 말을 했다.
  - '인사말로 시작하지 말고 핵심을 첫 문장에' 규칙과 모든 대사 '2문장 이내'는 넣어 봤다가 뺐다. 세 모델 모두 여전히 인사말로 시작했고, 문장 수 제한은 Mi:dm 에 변화가 없고 Kanana 를 더 잘리게 했다.
  - `personas.json` 의 `examplePolicy` · `attachmentPolicy` 같은 `…Policy` 칸은 사람이 읽는 메모라 프롬프트에 들어가지 않는다. 모델에 전하려면 이 규칙 문장(`run.py` 의 `RULE_…`)이나 도깨비 칸(`traits`, `speechStyle` 등)을 고친다.
  - llama.cpp 는 프롬프트 앞부분이 글자 하나까지 같으면 이미 읽은 것을 다시 쓴다. 실기기 시험에서 같은 도깨비가 이어진 장면(S03→S04, S05→S06)은 프롬프트 읽는 시간이 절반으로 줄었다. 예전에는 선택지별 말투가 시스템 메시지에 있어서 같은 도깨비라도 선택지가 바뀌면 앞부분이 달라졌다.
  - 게임은 도깨비를 탭해 확대할 때 이 시스템 메시지를 미리 읽혀 둔다(`NpcRequestManager.PrepareAsync`). 그러면 실제 요청 때는 사용자 메시지만 읽는다.
- **사용자 메시지**는 바뀌는 것을 담는다. 같은 상대면 앞부분이 이어지게 덜 바뀌는 것부터 싣는다.
  1. 지금 상대(주인/손님)와 그 상대를 대할 때의 태도
  2. 이번 후보 행동에 필요한 페르소나 칸만 — 감사에는 좋아하는 것·가치관이 필요 없다

     | 행동 | 싣는 칸 |
     |---|---|
     | `greet` | 가치관, 좋아하는 것 |
     | `answer_status` | 관리를 받으면 (좋아하는 것을 실으면 흐려진 상태 대신 날씨 이야기를 했다). 선명도가 흐려짐·재봉인이면 이것도 뺀다 — 실으면 Mi:dm 이 닦아 주지도 않았는데 "닦아 주셔서 감사합니다"라고 했다(S03) |
     | `recall_talk` | 없음 |
     | `thank_joyful` · `thank_calm` | 관리를 받으면 |
     | `struggle_protest` · `struggle_play` | 끌려갈 때 (싫어하는 것까지 실었더니 같은 걱정이 두 번 들어가, 밤바다가 시험마다 "옻칠에 지문 남지 않게 조심해"만 되풀이했다. 무엇을 걱정할지는 곁들일 거리가 바꾼다) |
     | `wander_greet` · `wander_recall` | 없음 |
  3. 상황, 알고 있는 것, 최근 이 상대와 있었던 일. '고른 선택지' 줄은 상황 문장과 겹치고, Mi:dm 이 '탭'을 'tap' 으로 옮겨 행동 칸에 적어서 뺐다. 각성 단계는 누구의 단계인지 몰라 "주인님께서 각성하셨으니"라고 해서(18:03 시험) 싣지 않는다
     - 안부의 상황 문장에는 할 말까지 짧은 문장으로 적는다(컨텍스트 구성기 `NpcContextBuilder` 와 같은 문장): "너는 오래 관리를 받지 못해 흐려졌다. 주인에게 닦아 달라고 부탁한다." / "너는 이틀 전에 닦아 관리를 받은 일이 고맙다."
       - 작은 모델은 상황 문장을 거의 그대로 대사로 옮긴다. 상황 문장이 어색하면 대사도 어색하다. "받은 덕분에 선명해서 고맙다"는 "닦아 주셔서 선명해져서 고마워요"가 됐다. '~서'로 잇지 않는다.
       - "9일 동안 관리를 받지 못해 흐려졌다"처럼 앞 문장이 길면 Kanana 의 부탁이 40자를 한 글자 넘겨 잘렸다(S03 0/3). 며칠인지는 사실 칸에만 둔다. 부탁을 이유보다 앞에 적어도 Kanana 는 흐려진 이야기부터 했다.
       - "이틀 전에 주인이 닦아 관리해 준 일을…"처럼 '주인이'를 넣으면 Kanana 가 주인에게 "주인이 닦아 관리해 주셔서"라고 그대로 옮겼다. 받은 쪽에서 쓴다.
  4. **떠올린 것** 한 줄 — "떠올린 것: 구름 무늬 (이것에 대한 느낌으로 말을 시작한다)". "어울릴 때만"으로 두었더니 거리를 건너뛰어 같은 말이 반복됐다(18:46: 구름결 이틀 전 관리 4번 중 3번 반복). "한마디 넣는다"로 두었더니 거리를 둘째 문장에 붙여, 첫 문장은 늘 상황 문장을 옮긴 "이틀 전에 닦아 주셔서 고마워요"였고 40자로 자르면 거리가 잘려 같은 대사만 남았다(20:02: S04 4번 중 2번이 반복으로 기본 대사). 그래서 바뀌는 거리로 말을 시작하게 한다. 같은 상황이 거듭될 때 대사가 갈리도록, 도깨비의 곁들일 거리(`personas.json` 의 `flavors`) 중 하나를 요청마다 돌려 싣는다. 아래 "같은 대사 줄이기"
  5. 후보와 대상의 뜻
  6. 대사 줄: "대사: 한국어, 25자 이내(짧아도 된다). 말투: 반말로만, '~요'·'~습니다' 없이" (손님 관람 20자). 말투 다짐은 도깨비의 `speechReminder` 다 — 말투가 시스템 메시지에만 있으면 작은 모델이 잊고 '~요'를 섞었다(18:46: 거른 이유의 대부분). 길이는 출력 토큰(=응답 시간)을 줄이려 30 → 25자로 줄였다(출력 검사 제한 40자는 그대로). 글자 수만 적으면 그 길이를 채우려고 말을 덧붙였다. 대화 기억이 있으면 "그때 한 말을 되풀이하지 말고…"를 붙인다
- **출력 형식 설명은 싣지 않는다.** "JSON 한 개만 출력한다", "출력 형식: {…}", "영문 그대로 적는다" 는 형식 제약(LM Studio 의 JSON 스키마, 기기의 GBNF)이 강제하는 것이라 뺐다. `--no-format` 으로 형식 제약을 끄면 사용자 메시지 끝에 붙인다.
- 말줄임표(…)는 말투 설명과 예시에 넣으면 거의 모든 대사에 붙어서 뺐다(`personas.json` 의 `ellipsisPolicy`).
## 같은 대사 줄이기

작은 모델은 프롬프트에 있는 문장을 그대로 옮기고, 프롬프트가 같으면 비슷한 대사를 낸다. 같은 상황마다 같은 말을 하면 지루하고 정이 들지 않는다.

- **곁들일 거리를 돌린다.** 프롬프트가 글자 하나 다르지 않으면 반복마다 비슷한 대사가 나왔다(17:29 시험: Kanana 구름결 흐려진 안부 4번이 모두 "오래 관리를 못 받아 흐려졌어요."로 시작, 반복안됨 Kanana 69% · Mi:dm 83% · EXAONE 85%). 그래서 도깨비마다 상황별 곁들일 거리 여러 개(`personas.json` 의 `flavors`)를 두고 요청마다 하나씩 "떠올린 것: 안개 (이것에 대한 느낌으로 말을 시작한다)" 줄로 싣는다. 거리는 상황마다 넷이다(셋이면 `--repeat 4` 의 넷째가 첫째와 같은 거리다).

  | 목록 | 쓰는 장면 |
  |---|---|
  | `tap` | 탭 인사 |
  | `faded` | 흐려짐·재봉인일 때 안부 |
  | `clear` | 선명할 때 안부, 관리 감사 |
  | `drag` | 끌려갈 때 |
  | `visit` | 손님 관람 |
  | (없음) | 지난 대화 꺼내기 — 그 기억 하나에 집중한다 |

  - 이 시험기는 반복 번호로 돌린다(1번째 반복 = 0번째 거리). 거리가 네 개라 `--repeat 4` 이상이면 다 본다. `--dry-run` 은 0번째를 보여 준다.
  - 게임은 컨텍스트 구성기가 요청마다 `ReactionRequest.Variation` 을 1씩 늘리고(도깨비·상대·선택지마다 따로 센다), 시작점은 날마다 옮긴다. 실기기 시험기(`NpcDeviceTestRunner`)도 반복 번호로 돌린다.
  - 곁들일 거리는 성향·생김새에서 고른 **한두 낱말의 이름씨**로 쓴다('구름 무늬', '지문'). 꾸밈말을 붙인 긴 거리('부딪힐까 조마조마한 날개', '또렷해진 구름 무늬')는 통째로 대사에 끼워 넣어 "또렷해진 구름 무늬가 정말 고마워요"처럼 어색했다(18:03 시험). 거리는 "그것에 대한 느낌"으로 쓰게 한다. 관리 받을 때 칸에 빗댈 거리("갠 하늘이나 학의 날개")를 함께 적으면 그 요청의 거리 대신 늘 그것을 써서(20:02: 거리가 '학'인데도 "맑게 갠 하늘처럼"), 빗댈 거리는 `flavors` 에만 둔다. 일어난 일("어제 약속한 일")이나 지금 시각·날씨는 넣지 않는다 — 지어낸 사건이 된다.
  - 출력 검사에 걸려 다시 만들 때도 다음 거리로 바꾼다.
- **옮겨 쓸 문장을 두지 않는다**(`personas.json` 의 `examplePolicy` · `fieldPolicy` · `speechPolicy`). 향산이 관리 감사 9번 중 5번이 "덕분에 향이 다시 맑아졌…"였다(16:48 시험).
  - 예시는 성향·습관처럼 언제 말해도 맞는 문장으로 쓰고, 지금 시각·날씨("오늘 밤", "햇볕 좋다")는 넣지 않는다. 주인에게 하는 말 같은 예시("주인께서 맡기신 일이라면…")는 주인 장면에서 통째로 옮겼다.
  - 관리 받을 때 · 끌려갈 때 같은 칸은 옮겨 쓸 문장 대신 태도와 빗댈 거리 두세 개로 쓴다("향 연기, 산바람, 깊은 숨 같은 것에 빗대기도 한다").
  - 말투에는 어미 조각("~구먼") 대신 활용한 낱말을 보여 주되, 인사·물음으로 바로 쓸 수 없는 낱말(좋다네, 그렇구먼, 맡기시오)로 고른다. "안녕하시오, 오셨구려", "왔구먼, 잘 지냈는가"를 넣었더니 그대로 대사가 됐고 처음 온 손님에게도 "잘 지냈는가"라고 했다(17:29). "계시오"를 넣었더니 탭 인사가 "안녕하시오, 계시오?"가 됐다(18:03) — 탭했으면 주인은 이미 있으니 인사로 맞지 않고 겹친다.
  - 의성어·헛기침("허허", "어흠", "히힛")은 감정 표현 칸 한 곳에만 둔다. 여러 곳에 두면 모든 대사가 같은 소리로 시작한다.

## 강제: 게임과 같은 출력 검사·다시 만들기

프롬프트 규칙만으로는 자기 이름·존댓말 반말 섞기·반복이 지켜지지 않아, 게임의 출력 검사기(`NpcOutputValidator` + `NpcLineChecks`)가 거르고 SLM 생성기가 다시 만든다. 이 시험기도 똑같이 한다(`game_problem`, `run_enforced`).

- 검사 순서는 게임과 같다: JSON → 후보 행동 → 대상 → (**말투 다듬기**) → 빈 대사 → 줄바꿈 → 길이 → 공통 금칙어 → **자기 이름** → **어미** → **반복**. 처음 걸린 것으로 거른다.
- **말투 다듬기**(`normalize_speech`, 게임의 `NpcLineChecks.NormalizeSpeech` 와 같다 — `Verify` 가 같은 예문으로 비교한다): 검사 전에 흔한 어미를 그 도깨비 말투(`endingHint.label`)로 고친다. 20:02 시험(Kanana)에서 거른 이유 63건 중 48건이 어미였고, 말투 규칙·다짐을 바꿔 가며 다섯 번 돌려도 말발굽(하오체)은 한 번도, 향산이(하게체)는 12번 중 0~2번만 첫 시도에 어미를 지켰다. 뜻은 맞는데 끝만 틀린 대사가 대부분이라 낱말 끝만 바꾼다. 19:53·20:02 결과에서 어미로 걸린 대사 69개 중 63개가 고친 뒤 통과한다.
  - 반말: "관리해 주셔서 정말 고마워요!" → "관리해 줘서 정말 고마워!", "왜 자꾸 저를 끌고 가요?" → "왜 자꾸 나를 끌고 가?", "주인아," → "주인님,"
  - 하오체: "안녕하십니까, 주인님." → "안녕하시오, 주인님.", "성실하게 주인님을 모시겠습니다." → "…모시겠소."
  - 하게체: "관리해주셔서 감사합니다." → "관리해줘서 감사하네.", "안녕하세요, 전시관을 둘러보시는군요." → "안녕하신가, 전시관을 둘러보시는구먼."
  - 해요체는(현재 쓰는 도깨비 없음) 고치지 않는다. 고치지 못한 것("즐거운 일이지요", "반갑습니다요")만 어미 검사가 거른다.
  - CSV 의 `다듬기전대사` 에 고치기 전 대사가, 요약의 `말투다듬음` 에 고친 비율이 나온다. `--no-normalize` 로 끄고 비교할 수 있다.
- 걸리면 곁들일 거리를 다음 것으로 바꿔 다시 만든다. `--attempts`(기본 2, 처음 포함)번 모두 걸리면 게임은 기본 대사를 띄운다(`최종` = 기본 대사). 모델 호출 오류는 다시 하지 않는다(게임도 그렇다).
- **어미**: `personas.json` 의 `endingHint`. `pattern` 은 문장마다 이렇게 끝나야 하고, `notPattern` 은 쉼표로 나뉜 마디까지 이렇게 끝나면 안 된다("좋은 하루 보내요, 천천히 구경하게"). 하오체·하게체도 '~요', '~니다'를 막는다. 감탄만 있는 짧은 문장·마디와 끝에 붙은 부르는 말("…하시오, 주인님.")은 빼고 본다.
- **반복**: 그 도깨비가 이 모델·방식에서 최근에 띄운 대사 5개(장면이 달라도 같은 도깨비면 함께, 게임의 `RecentLines`)와 비교한다. 띄어쓰기·문장부호를 빼고 ① 똑같거나 ② 이웃한 두 글자 묶음이 60% 넘게 겹치거나 ③ 짧은 쪽의 60% 넘게(5글자 이상) 긴 쪽에 그대로 들어 있거나 ④ 앞 10글자가 80% 넘게 겹치면 같은 대사다. "안부를 물어주셔서 정말 고마워요"와 "이틀 전에 닦아 주셔서 정말 고마워요"처럼 짧은 구절만 같은 것은 다르게 본다(예전 기준인 '8글자 같은 구절'은 이것도 같다고 봤다).
- CSV: `최종`(SLM / 기본 대사), `시도`(몇 번 만들었나), `거른이유`("1차 어미 섞임 '관리해줘서 고마워요!' / …"). 대사·검사 칸은 마지막 시도의 것이고, 응답ms·토큰은 모든 시도를 더한 값이다(플레이어가 기다리는 시간).
- 요약: `SLM대사`(기본 대사로 넘어가지 않은 비율), `첫시도통과`(한 번에 통과한 비율 — 프롬프트 자체의 품질), `시도(평균)`. `반복안됨` 은 화면에 띄운 대사(SLM 이거나 기본 대사)가 그 도깨비의 최근 대사와 다른지다. 기본 대사로 대신했으면 게임의 규칙 기반 생성기처럼 기본 대사를 골라 `띄운기본대사` 칸에 적고 최근 대사에도 넣는다(`대사` 칸은 마지막 시도의 모델 대사 그대로). 어미 검사는 감탄사만 있는 문장("어흠.", "히힛!")만 건너뛴다 — 짧은 문장을 다 건너뛰면 "고마워! 다시 오세요."의 "고마워!"를 놓쳤다.
- 이 검사로 이전 결과(17:29·18:03)를 다시 매기면 첫 시도 통과가 Kanana 50~52%, Mi:dm 27%, EXAONE 60% 였다. 걸린 이유는 어미가 가장 많았다(Kanana 13~16건, Mi:dm 22건).

## 자동 검사 중 손본 것 (2026-11-11 오후부터)

- `예시안베낌`: 예시를 통째로 옮긴 것뿐 아니라 **예시와 8글자 넘게 같은 구절**(띄어쓰기·문장부호 빼고)이 있으면 X 다. "어흠, 오늘 밤 순찰도 안전하게 마쳤습니다"처럼 예시를 고쳐 쓴 것도 잡는다.
- `금지어없음`: 장면 금지어에 **그 도깨비의 이름**을 더해 본다(자기 이름 부르기). 띄어쓰기는 빼고 찾는다("오늘 밤" = "오늘밤"). 그래서 모든 장면에서 판단한다.
- `어미(참고)`: 위 "강제"의 어미 검사와 같다.

## 대사 길이와 자르기

- 작은 모델은 두세 문장을 써서 길이(기본 40자, 손님 관람 25자)를 넘기는 일이 많다. 다 버리지 않고 **제한 안에 드는 앞 문장들만** 남긴다. 첫 문장부터 넘칠 때만 길이X 다. 게임의 출력 검사기와 같은 규칙이다.
  - 문장 끝: `.` `!` `?` `~` 뒤에 공백이나 글 끝. `…` · `...` 는 말줄임이라 끝이 아니다.
- 출력 토큰 한도는 64다(JSON 뼈대 약 20토큰 + 40자 대사 약 25토큰). 대사 중간에서 끊기면 닫아서 읽고 끝난 문장까지만 쓴다.
- CSV 의 `대사` 는 자른 대사, `자르기전대사` 는 원래 대사(잘랐을 때만), `문장자름` · `토큰한도끊김` 은 O/X 다. 요약에도 두 비율이 나온다.

## LM Studio로 돌리기

1. **모델 받기**: Discover 탭에서 모델을 검색해 내려받는다. 모바일에 올릴 크기를 보려면 GGUF의 Q4_K_M 양자화를 고른다. 모델마다 라이선스를 확인한다.
2. **서버 켜기**: Developer 탭에서 서버를 켠다(기본 포트 1234).
   - 설정에서 Just-in-Time 모델 로딩을 켜 두면 스크립트가 부를 때 모델이 자동으로 올라온다. 끄면 시험할 모델을 미리 로드해 둔다.
   - 메모리가 부족하면 다른 모델을 내리고 한 번에 하나씩 돌린다.
   - 새 모델이 로드되지 않으면 설정에서 llama.cpp 런타임을 최신으로 올린다.
3. **모델 이름 확인**:

   ```bash
   python run.py --backend lmstudio --list-models
   ```

4. **돌리기**: 목록에 나온 이름을 그대로 쓴다. (3번 반복)

   ```bash
   python run.py --backend lmstudio --models <모델이름> --variants single,two_step --repeat 3
   ```

   - 생각 모드는 기본적으로 끈다(`reasoning_effort: none`). 켜 두면 Gemma 4처럼 출력 한도를 생각에 다 쓰고 대사를 비워 돌려줄 수 있다. 비교하려면 `--allow-think` 를 붙인다.
   - LM Studio는 생성 시간을 따로 알려 주지 않아 초당토큰은 전체 응답 시간으로 어림한 값이다.
   - 서버 주소는 `localhost` 가 아니라 `127.0.0.1` 이다. Windows 에서 localhost 는 IPv6(::1)부터 붙어 보는데 LM Studio 는 IPv4 에서만 듣고, Windows 는 거절된 연결을 약 2초 붙잡다가 넘어간다. 2026-11-11 까지의 결과는 응답ms 에 이 2초가 들어 있다(세 모델 모두 '2초 + 출력 토큰당 약 55ms'). `--host` 로 주소를 줄 때도 127.0.0.1 로 쓴다.
   - 모델마다 처음에 길이가 다른 시스템 메시지로 짧게 두 번 불러 **시스템 메시지가 빠지지 않는지** 입력 토큰 수로 본다(`--system-in-user auto`). 시스템 메시지 없이 보내 비교하지 않는 것은, Mi:dm 처럼 시스템 메시지가 없으면 채팅 틀이 기본 문구를 넣는 모델이 있어서다. 빠지면 시스템 메시지를 사용자 메시지 앞에 붙여 보내고, CSV 의 `시스템합침` 이 O 다. EXAONE 4.0 1.2B 는 LM Studio 에서 시스템 메시지가 통째로 빠졌다(1,181자 프롬프트의 입력 토큰 245개, 같은 프롬프트로 Kanana 743개). 그래서 말투·'한국어로만' 규칙을 못 보고 영어로 답했으니, 그때까지의 EXAONE 결과는 페르소나 없이 낸 것이다.


## 프롬프트만 보기

모델 없이 프롬프트가 어떻게 만들어지는지 본다. LM Studio 채팅 창에 붙여 넣어 손으로 시험할 때도 쓴다.

```bash
python run.py --dry-run --variants single --scenes S05
```

## 옵션

| 옵션 | 뜻 |
|---|---|
| `--backend lmstudio` | LM Studio로 보낸다 |
| `--list-models` | 서버에서 쓸 수 있는 모델 이름을 보여 주고 끝낸다 |
| `--variants` | 돌릴 방식(아래 표). 기본은 전부 |
| `--scenes S01,S05` | 일부 장면만 |
| `--repeat N` | 장면마다 N번 반복. 행동 성향을 보려면 3 이상 |
| `--no-format` | JSON 스키마 형식 제약을 끄고, 대신 프롬프트에 출력 형식 설명을 싣는다. 형식 제약이 없는 런타임을 흉내 낼 때 쓴다 |
| `--num-predict 64` | 한 번에 생성할 최대 토큰. 기본 64 |
| `--think-off` | Ollama에서 생각 모드를 끈다 (qwen3 등). LM Studio는 기본으로 끈다 |
| `--allow-think` | LM Studio에서 생각 모드를 허용한다. 비교용 |
| `--seed N` | 결과를 재현하고 싶을 때 |
| `--line-chars 25` / `--max-chars 40` | 프롬프트에 적는 대사 길이 / 길이OK 판정 기준. 장면에 `lineChars` · `maxChars` 가 있으면 그 값을 쓴다 |
| `--max-sentences N` | 프롬프트에 "N문장 이내"를 적는다. 장면에 `maxSentences` 가 있으면 그 값을 쓴다. 기본 0 = 적지 않는다 |
| `--no-normalize` | 검사 전에 흔한 어미를 도깨비 말투로 고치는 단계를 끈다. 고치기 전과 비교할 때 쓴다 |
| `--attempts 2` | 출력 검사(자기 이름·어미 섞임·반복 등)에 걸리면 곁들일 거리를 바꿔 다시 만드는 횟수(처음 포함). 게임과 같은 기본 2. 1 이면 다시 만들지 않는다 |
| `--system-in-user auto\|on\|off` | 시스템 메시지를 사용자 메시지 앞에 붙여 보낸다. 기본 auto 는 LM Studio 에서 모델마다 시스템 메시지가 빠지는지 입력 토큰 수로 보고 빠질 때만 붙인다 |
| `--host` | 서버 주소를 바꿀 때. 기본은 `http://127.0.0.1:1234`(LM Studio), `http://127.0.0.1:11434`(Ollama). `localhost` 는 Windows 에서 요청마다 약 2초 늦다 |

## 비교하는 방식

| 방식 | 내용 | 결과로 정할 것 |
|---|---|---|
| `single` | 한 번 호출. 상황은 키-값, 예시 대사와 대화 기억 포함 | 기준선 |
| `facts_sentence` | 상황을 문장으로 | 요청의 Facts를 키-값으로 둘지 문장으로 둘지 |
| `no_examples` | 예시 대사를 뺌 | 페르소나 정의서에 예시가 필요한지 |
| `no_memory` | 대화 기억을 뺌 | Memory 필드가 필요한지 |
| `two_step` | 행동 선택과 대사 생성을 두 번에 나눔 | 생성기 안에서 한 번에 할지 나눌지 |

## 장면 구성

18개 장면은 짝을 지어 비교하도록 짰다. 짝끼리 결과가 달라야 페르소나와 상황이 반영된 것이다. 이야기 장면 5개는 이제 정해진 대사를 쓰므로 이 시험기는 건너뛰고, 실기기 시험과 `Verify` 의 규칙 기반 검사에만 쓴다.
번호는 예전 결과와 맞추려고 그대로 두었다. 
| 무엇을 보나 | 장면 | 같은 것 | 다른 것 |
|---|---|---|---|
| 말투 | S01 ↔ S02 | 주인 탭 인사 (행동 하나뿐) | 말발굽 의젓한 반말 / 묘작이 반말·의성어 |
| 상태에 따른 대사 | S03 ↔ S04 ↔ S12 | 구름결, 주인 안부 묻기 (행동은 안부 답하기 하나) | 흐려짐 → 관리 부탁 / 선명 + 이틀 전 관리 → 이력 떠올리기. 필수어포함으로 본다. S03 은 닦아 주지도 않았는데 고마워하면("닦아 주셔서", "선명해졌") 금지어에 걸린다 |
| 손님 관람 | S05 ↔ S06 ↔ S13 | 향산이, 걸으며 짧은 말풍선(Walking) | 첫 손님 → 지난 만남을 지어내지 않음 / 4번째 손님 → 알아보기 |
| 같은 돌봄 다른 성격 | S07 · S08 · S09 | 관리 완료 | 밤바다 담담 / 묘작이 기쁨 / 향산이 오랜 방치에도 느긋한 반가움 |
| 실화 이야기 (건너뜀) | S10 · S11 · S18 · S19 · S20 | 주인 이야기 듣기, 실화 한 문장 | AI 를 쓰지 않는다. `storyIndex` 번째 정해진 이야기 대사가 나오는지만 `Verify`·실기기 시험에서 본다 |
| 방치 정도 | S03 ↔ S12 | 향산이·구름결, 주인 안부 묻기 | 흐려짐(S03)과 다시 봉인(S12) 모두 서운함을 탓하지 않고 직접 부탁("닦아 줘")하는지. "닦아 달라고 부탁해" 같은 전해 들은 말투가 없어야 함 |
| 대화 기억 | S14 | 밤바다, 주인 안부 묻기 (행동은 지난 대화 꺼내기) | 지난 대화를 꺼내되 그대로 반복하지 않고, 주인에게 시키지 않음 |
| 끌어당기기 | S15 · S16 · S17 · S21 | 주인이 끌어당김, 버둥거림(Struggle) | 묘작이 놀이처럼 즐김 / 밤바다 투덜대도 밀어내지 않고 살살 다뤄 달라 함 / 구름결 깨질까 수줍게 조심해 달라 함. '놔'·'놓아'·'손대지 마'는 공통 금칙어로 잡는다 |

손님 장면(S05, S06, S13)에는 선명도를 넣지 않는다.
