# 도깨비 프롬프트 시험기

입출력 계약을 확정하기 전에, 실제 모델이 도깨비 반응을 쓸 만하게 만드는지 PC에서 확인하는 스크립트다.
장면마다 프롬프트를 만들어 로컬 모델(LM Studio)에 넣고, 자동 검사 결과를 CSV로 저장한다.
말투와 상황 반영 점수는 사람이 CSV에 직접 매긴다. Python 3.10 이상, 표준 라이브러리만 쓴다.

장면과 행동은 [터치 상호작용 기획안](../../docs/npc-touch-interaction-design.pdf)을 따른다.

- 주인이 NPC를 탭하면 포커스 줌 뒤 짧게 인사하고, 선택지(안부 묻기 · 관리하기 · 이야기 듣기)로 교류한다. 주인은 NPC를 끌어당겨 옮길 수도 있다.
- 손님은 도깨비를 건드릴 수 없고 전시관(건물·도깨비 배치)을 관람만 한다. 손님이 보는 동안 도깨비는 짧은 말풍선을 띄운 채 걸어 다닌다.
- 주인은 언제든 관리(재플레이)할 수 있어서 "조건 미충족" 상황은 없다.
- 행동은 4개 애니메이션(Idle · Walking · Positive · Struggle) 중 하나로 표현한다.
  - Talk는 아트의 w자 입 모양을 살리기 어려워 뺐다. 말하는 행동은 Idle에 말풍선으로 표현한다.
  - Struggle(버둥거림)은 NPC를 끌어당길 때 쓴다. 끌려갈 때는 **대사를 띄우지 않는다**(2026-11-13) — 모델도 부르지 않고 이 시험기도 건너뛴다.
  - Walking은 손님 관람 중 말풍선을 띄우고 걸을 때 쓴다.
  - Negative는 거절할 상황이 없어 뺐다. 불편함은 대사로 드러낸다.
- 놀람 · 수줍음 · 서운함 같은 세부 감정은 대사로 드러낸다.
- 지난 일은 저장된 이력이 있을 때만, 문화재 사실은 검수된 데이터(서버 시드의 `realStory`)로만 말한다.
- 대화의 목적은 플레이어가 상호작용을 통해 도깨비에게 **정이 들게 하는 것**이다. 무뚝뚝하거나 장난스러운 성격도 상대를 밀어내거나 깎아내리지 않는다. 욕설과 지나친 퉁명스러움은 공통 금칙어(`data/forbidden.json`)로 거른다.
- 도깨비마다 실화 이야기가 3개씩 있다(`personas.json` 의 `stories`). 이야기 듣기 때마다 게임이 돌려 가며 하나를 주어, 3개를 다 들려줄 때까지 같은 이야기를 반복하지 않는다.
- **이야기 듣기는 AI 로 만들지 않는다.** 2B 모델이 사실을 지어내거나 필요한 내용을 빼먹어서, 검수한 이야기 대사(`unity-npc-generator/Data/default_lines.json` 의 `stories`)를 차례로 쓴다. 이 시험기는 이야기 장면(S10 · S11 · S18 · S19 · S20)을 건너뛴다.

## 응답 시간 (2026-11-13: 실기기 30초대 → 3초 목표)

실기기(DEVICE_TEST.md)의 시간은 **읽는 토큰(프롬프트) + 쓰는 토큰(대사) + 다시 만들기**의 합이고, 그중 프롬프트 읽기가 가장 컸다(첫 응답까지 72~111초, 쓰기 6~11초). 그래서 읽는 글·쓰는 토큰·다시 만들기를 모두 줄였다.

| 줄인 것 | 전 → 후 |
|---|---|
| 시스템 메시지(도깨비마다 고정, 탭할 때 미리 읽는다) | 평균 971자 → 약 650자. 규칙을 해야 할 것만 짧게(`PromptAssembler.Rule…`). "~하지 않는다" 금지 문구를 모두 뺐다 |
| 사용자 메시지(요청마다 읽는다) | 평균 390자 → 약 260자(탭 인사 316 → 170자). 가치관 칸·시간대 사실·방문 횟수 사실·"대상 ID 뜻"·후보 목록을 빼고(행동이 하나면 `할 일: …` 한 줄), 호칭·상대 줄을 짧게, 손님 상황 문장은 한 문장으로 |
| 쓰는 토큰 | 문법(GBNF)·스키마를 모델이 적을 칸만 두어 `{"action": "greet", "target": "player", "line": "…"}`(뼈대 약 17토큰) → `{"line": "…"}`(약 5토큰). 출력 한도 64 → 40토큰. 대사는 "짧은 한 문장". 대사 문법은 문장 단위(문장마다 30자 안에 끝 부호) — 대사가 문장 중간에서 끊기지 않고 길게 늘어지지 않는다(`PromptOptions.SentenceGrammar`, 끄면 예전 문법). 2026-11-25부터 지난 대화 꺼내기·관리 감사만 두 문장까지, 그 밖은 끝 부호 전에 글자 5개 이상인 한 문장 — 출력 검사가 버리던 둘째 문장(실기기 모델 대사의 약 36%, 중앙값 13자 ≈ 1.5~2초)을 만들지 않는다. 기기(GBNF)에만 적용되고 이 시험기(LM Studio, JSON 스키마)에는 닿지 않는다 |
| 다시 만들기 | 최대 2번 그대로, 한 번 만드는 데 1.5초가 넘게 걸리면(느린 기기) 검사에 걸려도 다시 만들지 않고 곧바로 기본 대사로 (`RetryOnlyWithin`). 시험기 흉내는 `--retry-within 1.5` |
| 기다리는 시간 | `SlmTimeout` 기본 3초. 넘으면 기본 대사로 대신해 화면은 늦어도 3초 안에 반응한다 |

PC에서는 모델을 돌려 `입력토큰`·`출력토큰`·`응답ms` 를 비교한다. 기기의 실제 시간은 `NpcDeviceTestRunner` 의 "전체 시간 중앙값/90%"로 잰다.

### 실기기를 PC 속도에 가깝게 — 제안 (2026-11-14, 기기에서 재 보기 전의 추정이다)

PC(LM Studio) 중앙값은 약 2.2초(입력 650토큰 · 출력 25토큰 · 초당 13토큰)인데 기기는 몇 배 느리다. 먼저 `NpcDeviceTestRunner` 의 "미리 읽기 / 첫 응답 / 전체" 로 병목을 가른다 — **첫 응답이 길면 읽기(프리필) 병목, 첫 응답 뒤가 길면 쓰기 병목**이다.

| 순서 | 제안 | 효과 | 비용 |
|---|---|---|---|
| 1 | **미리 만들어 두기 — 구현함(2026-11-14, `NpcLineCache` · `NpcRequestManager.Prefetch`).** 탭 인사·관리 감사·손님 말풍선은 상황(도깨비·시간대·호칭)이 미리 정해진다. 전시관에 들어와 한가할 때 도깨비마다 대사를 1~2개 백그라운드로 만들어 큐에 두고, 요청이 오면 바로 꺼내 쓴다(큐가 비면 지금처럼 생성, 시간대가 바뀌면 버림). 최근 대사 검사와 그대로 맞물린다 | 체감 응답 ~0초 (생성은 사용자가 기다리지 않는 시간에) | 구현 끝. 기기 발열·배터리는 재 봐야 한다 |
| 2 | **늦게 끝난 대사를 버리지 않고 다음 요청에 쓴다.** 3초를 넘겨 기본 대사를 띄웠어도 모델은 끝까지 만든 대사를 큐에 넣는다 | 같은 기기에서 AI 대사 비율↑ | 작음 |
| 3 | **시스템 프롬프트 상태(KV)를 저장해 둔다 — 구현함(2026-11-14, `ILlmUnityStateStore` · `LlmUnityModelBackend.PrepareAsync`).** 도깨비 5명의 시스템 메시지를 처음 한 번만 읽고 llama.cpp 상태를 파일로 저장 → 앱을 다시 켜거나 도깨비를 바꿀 때 읽기 없이 불러온다. `LLMAgent.Save/Load` 이름은 LLMUnity 버전에 맞는지 확인해야 한다 | 첫 요청의 읽기 약 650토큰 → 0 | 구현 끝. 기기에서 재 봐야 한다 |
| 4 | **모델·양자화.** 2.1B Q4_K_M → 1B급(Gemma 3 1B, Qwen2.5 1.5B 등) 또는 ARM 용 Q4_0(llama.cpp 가 ARM 에서 자동 재배열) 으로 바꿔 같은 프롬프트로 대사 품질과 속도를 비교 | 읽기·쓰기 모두 1.5~2배 | 품질 재시험 |
| 5 | **런타임 설정.** 스레드 = 큰 코어 수(보통 4, 작은 코어 제외), batch/ubatch 512(읽기 병렬), flash-attn, KV 캐시 q8_0, 컨텍스트 2048 → 1024(프롬프트가 700토큰 안), iOS 는 Metal 전 레이어(99), 안드로이드는 Vulkan/OpenCL 오프로드를 기기마다 시험 | 읽기 1.3~2배 | 설정 시험 |
| 6 | **읽는 글을 더 줄인다.** 사용자 메시지 평균 약 260자 → 120자: 상대를 대하는 태도(`toOwner`·`toVisitor`)를 시스템 메시지(캐시됨)로 옮기고 사용자 메시지에는 "상대: 주인" 한 줄만 둔다(두 태도가 섞여 주인에게 손님 태도로 말한 문제는 "지금 상대는 주인" 줄로 막는다) | 요청마다 읽는 토큰 약 40% 감소 | 프롬프트 재시험 |
| 7 | **쓰는 토큰.** 문장 단위 문법과 40토큰 한도로 이미 줄였다. 더 줄이려면 대사를 15자 이내로, JSON 뼈대 없이 문장만 받는 문법으로(약 5토큰) | 쓰기 약 20% | 작음 |
| 8 | **기기 등급.** 측정한 "첫 응답 중앙값"이 3초를 넘는 기기는 SLM 을 끄거나, 1번의 미리 만들기만 쓰고 요청 때는 큐에서 꺼내 기본 대사로 대신한다 | 느린 기기도 늦지 않음 | 작음 |

1~2번은 모델이 느려도 사용자가 기다리지 않게 하는 방법이라 가장 확실하고, 3~5번은 생성 자체를 빠르게 하는 방법이다. 6~7번은 이미 한 일의 연장이다.

**`run.py` 의 응답 시간은 이 개선을 보여 주지 못한다 (2026-11-14 시험 3: 중앙값 2,218ms 로 그대로).** `run.py` 는 LM Studio 에 장면마다 처음부터 한 번씩 보내므로 ① 미리 만들어 둔 대사를 꺼내 쓰는 일(1번)도, ② 저장해 둔 시스템 메시지 기억을 되살리는 일(3번)도 일어나지 않는다. 이 값은 "모델이 한 번 읽고 쓰는 시간"(읽기 약 600토큰 + 쓰기 약 25토큰 ÷ 초당 13토큰)에 재시도(첫 시도 통과 79% → 시도 평균 1.21)가 얹힌 것이다. 프롬프트를 줄여 입력 토큰은 865~1,000 → 560~720 으로 줄었지만 시간의 대부분은 쓰기라 중앙값은 거의 같다. 1·3번의 효과는 실기기 시험 장면(`NpcDeviceTestRunner`, 요청 관리자 경유)의 "미리 만든 대사" 비율과 "미리 읽기 시간"(`LastPrepareRestored`)으로 본다.

## 프롬프트 구성

C# 프롬프트 조립기(`unity-npc-generator/Runtime/PromptAssembler.cs`)가 이 구성과 글자 하나까지 같은 프롬프트를 만든다(`Verify` 가 비교한다).

- **시스템 메시지는 도깨비마다 고정이다.** 이름·출신, 성격, 감정 표현, 말투, 예시 대사, 공통 규칙 여덟 줄만 싣는다.
  - **공통 규칙이 맨 앞, 도깨비마다 다른 것이 뒤 (2026-11-24)**: "너는 모바일 게임 '잠깨비'의 도깨비다." + 규칙 여덟 줄(`shared_system_head`, 343자)을 먼저 두고, 그 뒤에 "너는 ○○에 깃든 정령이다."·성격·말투·예시를 둔다.
    llama.cpp 는 앞 프롬프트와 글자 하나까지 같은 앞부분을 다시 읽지 않으므로, 다른 도깨비로 넘어가도 공통 부분(시스템 메시지의 60~70%)은 다시 읽지 않는다.
    예전에는 출신 문장이 첫 줄에 있어 도깨비가 바뀔 때마다 시스템 메시지를 처음부터 읽었다(기기 시험: 15~20초, 반복마다 아홉 번 안팎). 순서를 바꾼 뒤의 대사 품질은 아직 시험하지 않았다.
  - 18:46 시험(Kanana)에서 응답 중앙값이 5.3초로 늘었다. 첫 시도 통과가 29%라 평균 1.71번 만들었고, 규칙이 길어 입력 토큰이 약 800 → 1,040 개로 늘었다. 그래서 규칙은 뜻을 지키며 짧게 다시 썼고(규칙 780 → 494자), 말투 다짐을 대사 줄로 옮겼다. 행동 뜻을 대사로 읽어 "놀이처럼 신나서 버둥거려!"처럼 몸짓을 말해서, 행동 뜻(`actions.json` 의 `meaning`)도 몸짓 대신 '하는 말'로 쓰고 규칙에 '몸짓 설명은 넣지 않는다'를 넣었다.
  1. 애착 — 밀어내기·깎아내리기·평가하지 않기, **낮춰 부르거나 거만하게 말하지 않기**. 반말 도깨비가 "주인아"라고 불렀다. 낮춰 부르는 말은 늘어놓지 않고(오히려 쓴다) "주인아"·"손님아"는 공통 금칙어(`낮춰 부르기`)로 거른다. '주인님'·'손님'을 함께 적었더니 주인 장면에서 "손님께서"라고 해서 부르는 말은 적지 않는다(18:03 시험)
  2. 성격은 고르기와 말투에만, 세부 감정은 대사로
  3. 자료에 있는 것만. **지금이 낮인지 밤인지, 날씨도 자료에 없으면 말하지 않는다** — 게임이 접속 시각을 넘기지 않는데 예시의 "오늘 밤 순찰"을 옮겨 낮에도 '오늘 밤'이라고 했다
  4. **관리는 주인이 닦아 주는 일, 끌어당기기는 주인이 옮기는 일. 도깨비는 닦이고 옮겨지는 쪽**이고, **자기 몸과 기분은 남이 보듯 말하지 않고 느끼는 대로** — "닦을 수 있어서 고마워요", 끌려가며 "조심할게요", "개운해진 모습이 참 보기 좋네"라고 했다
  5. 한국어로만, **자기 이름을 말하지 않기**("반갑게요, 향산이"), 행동 이름 없이
  6. **친한 친구에게 말하듯 편한 반말로만 말하기** (모든 도깨비가 반말이라 공통 규칙으로 한 줄. 존댓말·옛말투 금지 목록은 적지 않는다)
  7. **고른 행동과 지금 상황에 꼭 맞는 말만, 짧은 문장 한두 개로 우리말 어순대로. 길이를 채우려고 말을 덧붙이거나 '~서'를 거듭 잇지 않기** — "이틀 전에 닦아 주셔서 선명해져서 고마워요", "부딪힐까 조마조마한 날개에 신경 쓰며, 손님께서 부드럽게 다뤄 주시면 좋겠어요"처럼 어색하거나 행동에 필요 없는 말을 붙였다
  8. 예시와 **아래 자료의 문장을 그대로 옮기지 않기**
  - 이름·어미·반복은 규칙만으로 지켜지지 않아 **출력 검사로 강제한다**(아래 "강제").
  - 기준 모델은 **Mi:dm 2.0 Mini** 다. 세 모델 비교(2026-11-11)에서 대사가 가장 짧고(문장자름 3%) 말투를 가장 잘 지켰다(어미일치 74%). Kanana 1.5 는 길게 써서 잘리고(문장자름 46%) 페르소나 칸을 그대로 옮겼고, EXAONE 4.0 1.2B 는 영어를 섞고 상황과 동떨어진 말을 했다.

  - `personas.json` 의 `examplePolicy` · `attachmentPolicy` 같은 `…Policy` 칸은 사람이 읽는 메모라 프롬프트에 들어가지 않는다. 모델에 전하려면 이 규칙 문장(`run.py` 의 `RULE_…`)이나 도깨비 칸(`traits`, `speechStyle` 등)을 고친다.
  - llama.cpp 는 프롬프트 앞부분이 글자 하나까지 같으면 이미 읽은 것을 다시 쓴다. 실기기 시험에서 같은 도깨비가 이어진 장면(S03→S04, S05→S06)은 프롬프트 읽는 시간이 절반으로 줄었다. 예전에는 선택지별 말투가 시스템 메시지에 있어서 같은 도깨비라도 선택지가 바뀌면 앞부분이 달라졌다.
  - 게임은 도깨비를 탭해 확대할 때 이 시스템 메시지를 미리 읽혀 둔다(`NpcRequestManager.PrepareAsync`). 그러면 실제 요청 때는 사용자 메시지만 읽는다.

- **출력 형식 설명은 싣지 않는다.** "JSON 한 개만 출력한다", "출력 형식: {…}", "영문 그대로 적는다" 는 형식 제약(LM Studio 의 JSON 스키마, 기기의 GBNF)이 강제하는 것이라 뺐다. `--no-format` 으로 형식 제약을 끄면 사용자 메시지 끝에 붙인다.
- 말줄임표(…)는 말투 설명과 예시에 넣으면 거의 모든 대사에 붙어서 뺐다(`personas.json` 의 `ellipsisPolicy`).
## 같은 대사 줄이기

작은 모델은 프롬프트에 있는 문장을 그대로 옮기고, 프롬프트가 같으면 비슷한 대사를 낸다. 같은 상황마다 같은 말을 하면 지루하고 정이 들지 않는다.

- **호칭 '님'·단골 오랜만·탭 거리**(2026-11-14 두 번째 시험): 호칭에 붙은 '님'은 거르지 않고 뗀다("도윤님"→"도윤", "발굴자님"→"발굴자", `strip_nim`). 호칭은 세 번에 한 번 "호칭: 도윤(한 번 불러 준다)"로 적어 가끔 대사에 나오게 한다(꼭은 아니다). 최근 방문이 7일 안인 단골의 "오랜만에"는 거르지 않고 "또"로 고친다(`fix_long_absence`; S13 은 8번 중 6번이 이것으로 기본 대사로 넘어갔다). 탭 인사·손님 관람에는 곁들일 거리 줄을 싣지 않는다("반가워서 내 말 그림 줬어"). "닦아줄게"(닦이는 쪽이 닦아 주겠다)·"힘들었구나"(주인을 위로)는 거르고, "닦아 달라고 부탁드리고 싶어요"는 "닦아 줘"로 고친다(전에는 "닦아 줘드리고 싶어").
- **어색한 시작·끊긴 대사·부탁 빠짐**(2026-11-14 시험): 첫 낱말에서 "잘"("잘 왔지? 다음엔 꼭 같이 가자!"처럼 없는 약속)과 "오늘은"("오늘은 관리해 줘서 고마워")을 뺐고, 곁들일 거리 힌트는 "(내 이야기)"로 바꿨다. "같이 가자"·"다음엔 꼭"·"발굴자님"(2026-11-17까지는 "발굴자가"도 금칙어였으나, 아래 "2인칭 대신 호칭"으로 이제 허용한다)·"~했다."류 설명투 끝은 금칙어로 거른다. 자기 모습을 "네 모습"이라고 하지 않는다(`ownThings` 에 '모습'). 첫 낱말 뒤 쉼표("덕분에,")는 뗀다. 흐려진 안부에 닦아 달라는 부탁이 없으면 거른다(`has_ask`). 토큰 한도에서 '}' 만 빠진 JSON 도 읽는다.
- **첫 낱말을 돌린다**(2026-11-13 네 번째 시험): 프롬프트를 줄였더니 관리 감사가 거의 모두 "관리해 줘서 고마워"로 같았다(같은 시나리오 4번 중 3~4번, 다시 만들어도 같아 기본 대사로 넘어갔다). 요청마다 다른 첫 낱말을 하나 정해 "첫 낱말: 덕분에" 줄로 싣는다(`PromptAssembler.Starter`, `run.py starter_word`). 상황마다 여섯(탭 "안녕·왔구나·어서…", 흐려진 안부 "몸이·조금·요즘…", 선명한 안부·관리 "덕분에·이제·한결…", 손님 "안녕·어서·반가워…", 단골 "자주·이번에도·또…" — 단골에는 "오랜만"을 부르는 말을 피한다)이고 곁들일 거리와 같은 번호로 돌려, 다시 만들 때도 달라진다. 곁들일 거리의 힌트는 "이 느낌을 곁들인다"로 바꿨다. 도깨비마다 기본 감사 대사도 2개 → 5개로 늘려, 모델 대사를 거른 뒤에도 같은 말만 나가지 않게 했다.
- **곁들일 거리를 돌린다.** 프롬프트가 글자 하나 다르지 않으면 반복마다 비슷한 대사가 나왔다(17:29 시험: Kanana 구름결 흐려진 안부 4번이 모두 "오래 관리를 못 받아 흐려졌어요."로 시작, 반복안됨 Kanana 69% · Mi:dm 83% · EXAONE 85%). 그래서 도깨비마다 상황별 곁들일 거리 여러 개(`personas.json` 의 `flavors`)를 두고 요청마다 하나씩 "떠올린 것: 안개 (이것에 대한 느낌으로 말을 시작한다)" 줄로 싣는다. 거리는 상황마다 넷이다(셋이면 `--repeat 4` 의 넷째가 첫째와 같은 거리다).

  | 목록 | 쓰는 장면 |
  |---|---|
  | `tap` | 탭 인사 |
  | `faded` | 흐려짐·재봉인일 때 안부 |
  | `clear` | 선명할 때 안부, 관리 감사 |
  | `drag` | 끌려갈 때 |
  | `visit` | 손님 관람 |
  | (없음) | 지난 대화 꺼내기 — 그 기억 하나에 집중한다 |

  - 이 시험기는 반복 번호로 돌린다(1번째 반복 = 0번째 거리). 거리가 네 개라 `--repeat 4` 이상이면 다 본다. `--dry-run` 은 0번째를 보여 준다.
  - 게임은 컨텍스트 구성기가 요청마다 `ReactionRequest.Variation` 을 1씩 늘리고(도깨비·상대·선택지마다 따로 센다), 시작점은 날마다 옮긴다. 실기기 시험기(`NpcDeviceTestRunner`)도 반복 번호로 돌린다.
  - 곁들일 거리는 성향·생김새에서 고른 **한두 낱말의 이름씨**로 쓴다('구름 무늬', '지문'). 꾸밈말을 붙인 긴 거리('부딪힐까 조마조마한 날개', '또렷해진 구름 무늬')는 통째로 대사에 끼워 넣어 "또렷해진 구름 무늬가 정말 고마워요"처럼 어색했다(18:03 시험). 거리는 "그것에 대한 느낌"으로 쓰게 한다. 관리 받을 때 칸에 빗댈 거리("갠 하늘이나 학의 날개")를 함께 적으면 그 요청의 거리 대신 늘 그것을 써서(20:02: 거리가 '학'인데도 "맑게 갠 하늘처럼"), 빗댈 거리는 `flavors` 에만 둔다. 일어난 일("어제 약속한 일")이나 지금 시각·날씨는 넣지 않는다 — 지어낸 사건이 된다.
  - 출력 검사에 걸려 다시 만들 때도 다음 거리로 바꾼다.
- **옮겨 쓸 문장을 두지 않는다**(`personas.json` 의 `examplePolicy` · `fieldPolicy` · `speechPolicy`). 향산이 관리 감사 9번 중 5번이 "덕분에 향이 다시 맑아졌…"였다(16:48 시험).
  - 예시는 성향·습관처럼 언제 말해도 맞는 문장으로 쓰고, 지금 시각·날씨("오늘 밤", "햇볕 좋다")는 넣지 않는다. 주인에게 하는 말 같은 예시("주인께서 맡기신 일이라면…")는 주인 장면에서 통째로 옮겼다.
  - 관리 받을 때 · 끌려갈 때 같은 칸은 옮겨 쓸 문장 대신 태도와 빗댈 거리 두세 개로 쓴다("향 연기, 산바람, 깊은 숨 같은 것에 빗대기도 한다").
  - (2026-11-13: 말투 줄에서 어미 조각·활용 예·금지 목록을 모두 뺐다. 작은 모델이 금지 목록의 말('~구먼', '~하게')을 그대로 옮겼다. 말투는 캐릭터 말씨만 적고, 반말은 공통 규칙, 옛말투는 `endingHint.bannedPattern` 이 거른다.) 이전 기록: 말투에는 어미 조각("~구먼") 대신 활용한 낱말을 보여 주되, 인사·물음으로 바로 쓸 수 없는 낱말(좋다네, 그렇구먼, 맡기시오)로 고른다. "안녕하시오, 오셨구려", "왔구먼, 잘 지냈는가"를 넣었더니 그대로 대사가 됐고 처음 온 손님에게도 "잘 지냈는가"라고 했다(17:29). "계시오"를 넣었더니 탭 인사가 "안녕하시오, 계시오?"가 됐다(18:03) — 탭했으면 주인은 이미 있으니 인사로 맞지 않고 겹친다.
  - 의성어·헛기침("허허", "어흠", "히힛")은 감정 표현 칸 한 곳에만 둔다. 여러 곳에 두면 모든 대사가 같은 소리로 시작한다.

## 강제: 게임과 같은 출력 검사·다시 만들기

프롬프트 규칙만으로는 자기 이름·존댓말 반말 섞기·반복이 지켜지지 않아, 게임의 출력 검사기(`NpcOutputValidator` + `NpcLineChecks`)가 거르고 SLM 생성기가 다시 만든다. 이 시험기도 똑같이 한다(`game_problem`, `run_enforced`).

- 검사 순서는 게임과 같다: JSON → 후보 행동 → 대상 → (**말투 다듬기**) → 빈 대사 → 줄바꿈 → 길이 → 공통 금칙어 → **자기 이름** → **어미** → **반복**. 처음 걸린 것으로 거른다.
- **말투 다듬기**(`normalize_speech`, 게임의 `NpcLineChecks.NormalizeSpeech` 와 같다 — `Verify` 가 같은 예문으로 비교한다): 검사 전에 흔한 어미를 그 도깨비 말투(`endingHint.label`)로 고친다. 20:02 시험(Kanana)에서 거른 이유 63건 중 48건이 어미였고, 말투 규칙·다짐을 바꿔 가며 다섯 번 돌려도 말발굽(하오체)은 한 번도, 향산이(하게체)는 12번 중 0~2번만 첫 시도에 어미를 지켰다. 뜻은 맞는데 끝만 틀린 대사가 대부분이라 낱말 끝만 바꾼다. 19:53·20:02 결과에서 어미로 걸린 대사 69개 중 63개가 고친 뒤 통과한다.
  - 반말: "관리해 주셔서 정말 고마워요!" → "관리해 줘서 정말 고마워!", "왜 자꾸 저를 끌고 가요?" → "왜 자꾸 나를 끌고 가?", "주인아," → "주인님,"
  - 하오체: "안녕하십니까, 주인님." → "안녕하시오, 주인님.", "성실하게 주인님을 모시겠습니다." → "…모시겠소."
  - 하게체: "관리해주셔서 감사합니다." → "관리해줘서 감사하네.", "안녕하세요, 전시관을 둘러보시는군요." → "안녕하신가, 전시관을 둘러보시는구먼."
  - 해요체는(현재 쓰는 도깨비 없음) 고치지 않는다. 고치지 못한 것("즐거운 일이지요", "반갑습니다요")만 어미 검사가 거른다.
  - CSV 의 `다듬기전대사` 에 고치기 전 대사가, 요약의 `말투다듬음` 에 고친 비율이 나온다. `--no-normalize` 로 끄고 비교할 수 있다.
- 걸리면 곁들일 거리를 다음 것으로 바꿔 다시 만든다. `--attempts`(기본 2, 처음 포함)번 모두 걸리면 게임은 기본 대사를 띄운다(`최종` = 기본 대사). 모델 호출 오류는 다시 하지 않는다(게임도 그렇다).
- **어미**: `personas.json` 의 `endingHint`. `pattern` 은 문장마다 이렇게 끝나야 하고, `notPattern` 은 쉼표로 나뉜 마디까지 이렇게 끝나면 안 된다("좋은 하루 보내요, 천천히 구경하게"). 하오체·하게체도 '~요', '~니다'를 막는다. 감탄만 있는 짧은 문장·마디와 끝에 붙은 부르는 말("…하시오, 주인님.")은 빼고 본다.
- **대사 품질**(2026-11-13 두 번째 시험): 최근 대사는 **시나리오(같은 도깨비의 같은 선택지)마다 10개**를 기억하고(`RECENT_LINES`), 10개 중 하나와 90% 이상 겹치면 새로 만든다(`--attempts` 기본 2 그대로). 오타(`typo`: 쏟었군·할께·ㅋㅋ…)와 끊긴 문장(`incomplete_ending`: "관리해 줘서")을 거르고, 대사 끝의 의성어(`히힛!`)는 말투 다듬기가 뗀다(`strip_trailing_interjection`). 높임 빼기의 버그를 고쳤다 — `으셨`은 모음에 따라 `았`/`었`(쏟으셨→쏟았), `만드셨`→`만들었`(전에는 "만먹었는지"). 3일 전에도 온 친구에게 "오랜만"은 거른다(`long_absence_contradiction`), 예시 대사를 8글자 넘게 옮겨도 거른다(`persona_copy`). 탭 상황은 "주인이 아침에 너를 탭했다"로 시간대를 녹였다.
- **대사 질 보정**(2026-11-16 두 번째 시험 64건): 첫 시도 통과 56→77%, 시도 1.44→1.23, 응답 2572→2047ms 로 좋아졌지만 플레이어가 보기에 어색한 대사가 늘었다(S09 #4 기본 대사·S12 #1~#4). 시간·통과율을 지키려고 다시 만드는 횟수를 늘리지 않는 쪽으로 고쳤다. ① 부탁하는 말의 주어 '주인이/주인님께서'는 "네가"로 바꾸지 않고 지운다(`REQUEST_SUBJECT_RE`): "네가 닦아줘"·"혹시 네가 닦아 주면…"이 너에게 시키는 말처럼 들렸다. 고마움("주인이 관리해 줘서")은 그대로 "네가". ② "닦아줘 줘" 같은 끝말 되풀이를 하나로 합친다(`collapse_double_verb`). ③ 금칙어(`forbidden-18`): 서술체 "~떠올렸다."(`렸|났|켰|겼|쳤|봤` 추가)와 맞이하는 상황의 작별 인사("잘 다녀와~" — 새 `farewell` 묶음)를 거른다. ④ 탭 상황 문장을 "너를 탭했다"에서 "너를 불렀다"로 바꿨다 — 모델이 화면 조작 용어 "탭해"를 따라 말해 금칙어에 걸린 3건(S01 #3·#4, S24 #2)을 없앤다. 새 규칙이 거르는 것은 이전 SLM 대사 58건 중 2건(S13 #4, S14 #1)이라 통과율은 3% 안팎만 내려가고 ④가 그만큼 올린다. 모델로 다시 재서 확인한다.
- **'?'를 묻는 말에만**(2026-11-16 22:33 기록: 첫시도통과 69%, 시도 1.31, 응답 2340ms, 호칭OK 100%): "오늘 아침부터 바쁘네?"·"나를 부르네?"처럼 묻는 말이 아닌데 '?'로 끝낸 대사가 나왔다. ① 코드: 감탄·서술 끝맺음(~네·~군·~구나·~더라) 뒤의 '?'는 '.'로 고친다(`fix_statement_question`, C# `FixStatementQuestion`). 묻는 말("왔어?"·"볼래?"·"있지?")과 "네?"는 그대로. ② 규칙: 순서 규칙 끝에 "묻는 말만 ?로 끝낸다."를 붙였다(시스템 규칙 전체 350자 제한 안, 도깨비마다 한 번 읽는 시스템 메시지라 요청 시간은 늘지 않는다). 모델로 다시 재서 `거른이유`·`첫시도통과`가 그대로인지, 말끝 '?'가 줄었는지 본다.
- **응답 시간 2초대 초반으로**(2026-11-16 20:58 기록 정리): 응답 중앙값 2.4초는 다시 만든 28건(33%, 3~5초)이 끌어올린 값이고 한 번에 통과한 43건은 2.05초였다. 응답 ms ≈ 680 + 63 × 출력 토큰이라 줄이는 길은 둘이다. ① 다시 만드는 일 줄이기: 높임 고치기("부르셔서" 6건)로 첫 시도에서 살린다. ② 출력 토큰 줄이기: 탭 인사·손님 관람 말풍선의 글자 수 목표를 20자 → 15자로(`INPUT_LINE_CHARS`, C# `PromptOptions.LineChars`). 20자로 적었더니 모델이 중앙값 25자(24토큰)를 썼다. 15자면 약 19자·18토큰이라 0.3초가량 빨라진다. 감사·안부는 정보가 들어가고 15자로 줄이면 "관리해 줘서 고마워."만 되풀이될 위험이 있어 20자 그대로다. 장면에 박아 둔 `lineChars: 20`(S05·S06·S13·S25)은 이 기본값을 가려서 뺐다. 또 상황 설명문이 끊긴 채 대사로 나간 것("찾아와서 반갑게 인사하며 '오늘은 …", S01 #3)은 지문 금칙어(`forbidden-20`: 인사하며·웃으며·덧붙였·라고 말했, 동사 뒤 따옴표)와 "따옴표가 열린 채 끊긴 마디는 `fit_clause` 가 건지지 않는다"로 막는다. 모델로 다시 재서 `응답ms(중앙값)` 이 2.0~2.2초 대인지, `첫시도통과`·`시도(평균)`·`반복안됨` 이 그대로인지 본다.
- **세 번째 시험 정리**(2026-11-16 20:58, 64건: 첫시도통과 67%, 시도 1.33, 응답 2421ms): 탭 상황을 "너를 불렀다"로 바꾸자 모델이 "부르셔서 반가워"처럼 높여 말해 어미 섞임('셔')으로 걸려, S22 #4·S23 #1·#4·S24 #3 이 다시 만들다 기본 대사로 넘어갔다. 높임을 고쳐서 살린다: 르 불규칙(부르셔서→불러서·부르셨→불렀·부르신→부른)·우 불규칙(깨우셔서→깨워서)·'으셔'(찾으셔서→찾아서), '기쁩니다'류 합쇼체(기쁩니다→기뻐). '어르신'은 건드리지 않는다. 또 없는 선물 약속("따뜻한 우유 줄게?", S02 #2)은 금칙어(`forbidden-19`)로 거른다. S07 #2·#3 처럼 같은 감사 대사("관리해 줘서 고마워.")가 거듭 나오는 것은 모델이 첫 낱말을 따르지 않는 탓이라 규칙으로 고치지 못했다(반복 검사가 막아 기본 대사로 넘어간다).
- **플레이어 호칭은 둘 중 하나로**(2026-11-16): 친밀도에 따라 '발굴자'(0~2단계)나 닉네임(3단계 이상) 하나로만 부른다. 모델이 "친구야,"·"손님,"·틀린 쪽 호칭으로 **부르면**(뒤에 쉼표·느낌표·물음표) 거르지 않고 맞는 쪽으로 바꾼다(`unify_player_call`, 닉네임이면 받침에 맞게 아·야). "친구가 왔네"·"내 친구야"처럼 문장 안의 말은 건드리지 않고, 문장 안에서 틀린 호칭을 말한 것만 기존대로 `호칭이 규칙과 다름`으로 거른다.
- **주체 어긋남 검사·쉼표 단위 자르기**(2026-11-16 시험 64건): 한 번 걸러 다시 만든 것이 28건이고 그 응답은 중앙값 3.4초(처음에 통과하면 1.9초)였다. 게임은 첫 시도가 1.5초를 넘으면 다시 만들지 않고 기본 대사로 넘어가므로 첫 시도 통과율(56%)을 올리는 것이 속도와 품질에 모두 가장 크다. ① `subject_contradiction`: 자기 것(`ownThings`)을 '내 ~' 없이 구경하듯 말한 대사("오, 자개가 정말 공들여 만든 거네 덕분에 빛나네.")를 거른다 — 거른이유 "주체가 어긋남". ② `fit_clause`: 첫 문장이 길이 제한을 넘어도("길이 초과" 6건) 쉼표 앞 마디가 끝난 말이면 그것만 쓴다(5글자 이상, 끝 글자가 어미). 다시 만드는 1.5~2초를 아낀다. 효과는 모델로 다시 재서 `시도(평균)`·`첫시도통과`·`응답ms(중앙값)` 와 거른이유의 "주체가 어긋남" 건수로 확인한다.
- **어색한 말·문법·반복 줄이기**(2026-11-17, 2026-11-16 22:49 시험 64건: 첫시도통과 66%, 시도 1.34, 반복안됨 96%, 말투다듬음 50%). 사람이 읽어 보니 걸러지지 않은 어색한 대사가 많았고, 원인은 넷이었다.
  1. **탭 인사의 시간대**: 상황 문장 "주인이 아침에 찾아와 너를 불렀다"의 '아침'을 모델이 늘 옮겨 탭 인사 12건 중 9건이 "오늘 아침부터 …"였다("오늘 아침부터 왜 부르는지 궁금하네", "반가워, 오늘 아침부터 부르시니 정말 반가워"). 시간대는 세 번에 한 번(`variation % 3 == 0`)만 싣는다(`event_text`, C# `PromptAssembler.EventText`). 출력 검사의 시간대 어긋남(`time_contradiction`)은 그대로다.
  2. **없는 사정 지어내기**: 행동 뜻 "반갑게 인사하고 한마디를 덧붙인다"와 규칙 "곁들일 거리나 지금 상황의 한마디를 덧붙여"를 읽은 모델이 "궁금한 점이 많겠네", "오늘 밤은 너무 재미있었어", "오늘 하루는 평온할 것 같지?"를 지어냈다. 뜻을 "반갑게 맞이하는 짧은 말을 한다"로, `RULE_VARY` 를 "첫 낱말과 떠올린 것에 맞춰 짧게, 매번 다르게 말한다."로 바꿨다. 탭 첫 낱말에서 "찾아와서"(방문과 부름을 뒤섞음)·"만나서"("만나서 반가워"로 거의 같게 시작)를 빼고 "기다렸어"를 더했다(여섯 → 다섯). 이런 말은 금칙어 `awkward` 가 거른다(`왜 부르/왔`·`궁금한 점`·`밤은 재미/따뜻…`·`하루 … 것 같지`·`재밌나 봐`·`구경 잘 돼`·`반갑게 인사해`·`깨우러`·`닦아 줘서 … 주면/줘/좋겠`).
  3. **다듬기가 만든 어색함**: ① 호칭을 지우며 쉼표까지 지워 마디가 붙었다("예쁘네, 주인님 덕분에" → "예쁘네 덕분에") — 뒤에 말이 이어지면 쉼표를 남긴다(`_kept_comma`). ② 높임이 남았다("부르시다니", "보여드릴") — `시` 뒤 `다니·더니·면서·거나·든지·느라`, `드릴`→`줄`. ③ 프롬프트의 사실 칸 이름 "몸 상태"를 옮겨 자기 몸을 남이 재듯 말했다("몸 상태가 선명해졌어") — "몸이"로(`fix_body_state`). ④ 손님에게 "편하게 구경해 줘" — 권하는 말 "구경해"로(`OFFER_ASK_RE`). ⑤ "또 왔구나! 반가워, 오랜만이야!"의 "오랜만이야"를 "또 왔네"로 바꿔 겹쳤다 — 이미 "또"가 있으면 "반가워"로. ⑥ "처음 온 친구야!"(서술)를 부르는 말로 보고 "처음 온 발굴자!"로 바꿨다 — 앞말 `온` 은 건드리지 않는다.

  4. **문법으로 막을 수 있는 것을 낱말로 막고 있었다**: 자기 몸·마음·감사를 말하는데 남의 일을 알아챈 어미 "~는구나·~구나·~군"을 쓰면("뛰는구나!", "만들었구나") 자기를 남 얘기하듯 한 것이다 — 감사·안부·기억 행동의 문장 끝에 이 어미가 오면 거른다(`discovery_ending`; 인사의 "왔구나"는 상대를 보고 하는 말이라 허용).
  **코드 구조 소견**: 말투 다듬기·출력 검사가 수십 개의 문자열 고침으로 자라 서로 어긋난 결과를 만들었고(지우기·치환 뒤 남는 토막), 같은 규칙이 Python·C# 두 곳과 문구를 직접 비교하는 테스트에 퍼져 있어 한 번 바꾸면 여러 곳이 깨진다. 그래서 앞으로는 ① 고치기는 치환만, 지우기는 안전할 때만 ② 사실은 코드가 서버 값으로 ③ 모델은 짧은 한 조각만 ④ 문법으로 말할 수 있는 규칙은 낱말 금지보다 먼저 — 순으로 한다. 같은 방식(사실 문장은 코드, 모델은 한 조각)을 감사·인사로 넓힐지는 모델로 재 보고 정한다.

## 대사 길이와 자르기

- 작은 모델은 두세 문장을 써서 길이(기본 40자, 손님 관람 25자)를 넘기는 일이 많다. 다 버리지 않고 **제한 안에 드는 앞 문장들만** 남긴다. 첫 문장부터 넘칠 때만 길이X 다. 게임의 출력 검사기와 같은 규칙이다.
  - 문장 끝: `.` `!` `?` `~` 뒤에 공백이나 글 끝. `…` · `...` 는 말줄임이라 끝이 아니다.
- 출력 토큰 한도는 64다(JSON 뼈대 약 20토큰 + 40자 대사 약 25토큰). 대사 중간에서 끊기면 닫아서 읽고 끝난 문장까지만 쓴다.
- CSV 의 `대사` 는 자른 대사, `자르기전대사` 는 원래 대사(잘랐을 때만), `문장자름` · `토큰한도끊김` 은 O/X 다. 요약에도 두 비율이 나온다.

## LM Studio로 돌리기

1. **모델 받기**: Discover 탭에서 모델을 검색해 내려받는다. 모바일에 올릴 크기를 보려면 GGUF의 Q4_K_M 양자화를 고른다. 모델마다 라이선스를 확인한다.
2. **서버 켜기**: Developer 탭에서 서버를 켠다(기본 포트 1234).
   - 설정에서 Just-in-Time 모델 로딩을 켜 두면 스크립트가 부를 때 모델이 자동으로 올라온다. 끄면 시험할 모델을 미리 로드해 둔다.
   - 메모리가 부족하면 다른 모델을 내리고 한 번에 하나씩 돌린다.
   - 새 모델이 로드되지 않으면 설정에서 llama.cpp 런타임을 최신으로 올린다.
3. **모델 이름 확인**:

   ```bash
   python run.py --backend lmstudio --list-models
   ```

4. **돌리기**: 목록에 나온 이름을 그대로 쓴다. (3번 반복)

   ```bash
   python run.py --backend lmstudio --models <모델이름> --variants single,two_step --repeat 3
   ```

   - 생각 모드는 기본적으로 끈다(`reasoning_effort: none`). 켜 두면 Gemma 4처럼 출력 한도를 생각에 다 쓰고 대사를 비워 돌려줄 수 있다. 비교하려면 `--allow-think` 를 붙인다.
   - LM Studio는 생성 시간을 따로 알려 주지 않아 초당토큰은 전체 응답 시간으로 어림한 값이다.
   - 서버 주소는 `localhost` 가 아니라 `127.0.0.1` 이다. Windows 에서 localhost 는 IPv6(::1)부터 붙어 보는데 LM Studio 는 IPv4 에서만 듣고, Windows 는 거절된 연결을 약 2초 붙잡다가 넘어간다. 2026-11-11 까지의 결과는 응답ms 에 이 2초가 들어 있다(세 모델 모두 '2초 + 출력 토큰당 약 55ms'). `--host` 로 주소를 줄 때도 127.0.0.1 로 쓴다.
   - 모델마다 처음에 길이가 다른 시스템 메시지로 짧게 두 번 불러 **시스템 메시지가 빠지지 않는지** 입력 토큰 수로 본다(`--system-in-user auto`). 시스템 메시지 없이 보내 비교하지 않는 것은, Mi:dm 처럼 시스템 메시지가 없으면 채팅 틀이 기본 문구를 넣는 모델이 있어서다. 빠지면 시스템 메시지를 사용자 메시지 앞에 붙여 보내고, CSV 의 `시스템합침` 이 O 다. EXAONE 4.0 1.2B 는 LM Studio 에서 시스템 메시지가 통째로 빠졌다(1,181자 프롬프트의 입력 토큰 245개, 같은 프롬프트로 Kanana 743개). 그래서 말투·'한국어로만' 규칙을 못 보고 영어로 답했으니, 그때까지의 EXAONE 결과는 페르소나 없이 낸 것이다.


## 프롬프트만 보기

모델 없이 프롬프트가 어떻게 만들어지는지 본다. LM Studio 채팅 창에 붙여 넣어 손으로 시험할 때도 쓴다.

```bash
python run.py --dry-run --variants single --scenes S05
```

## 옵션

| 옵션 | 뜻 |
|---|---|
| `--backend lmstudio` | LM Studio로 보낸다 |
| `--list-models` | 서버에서 쓸 수 있는 모델 이름을 보여 주고 끝낸다 |
| `--variants` | 돌릴 방식(아래 표). 기본은 전부 |
| `--scenes S01,S05` | 일부 장면만 |
| `--repeat N` | 장면마다 N번 반복. 행동 성향을 보려면 3 이상 |
| `--no-format` | JSON 스키마 형식 제약을 끄고, 대신 프롬프트에 출력 형식 설명을 싣는다. 형식 제약이 없는 런타임을 흉내 낼 때 쓴다 |
| `--num-predict 40` | 한 번에 생성할 최대 토큰. 기본 40 (게임의 `MaxTokens` 와 같다) |
| `--think-off` | Ollama에서 생각 모드를 끈다 (qwen3 등). LM Studio는 기본으로 끈다 |
| `--allow-think` | LM Studio에서 생각 모드를 허용한다. 비교용 |
| `--seed N` | 결과를 재현하고 싶을 때 |
| `--line-chars 25` / `--max-chars 40` | 프롬프트에 적는 대사 길이 / 길이OK 판정 기준. 장면에 `lineChars` · `maxChars` 가 있으면 그 값을 쓴다 |
| `--max-sentences N` | 프롬프트에 "N문장 이내"를 적는다. 장면에 `maxSentences` 가 있으면 그 값을 쓴다. 기본 0 = 적지 않는다 |
| `--no-normalize` | 검사 전에 흔한 어미를 도깨비 말투로 고치는 단계를 끈다. 고치기 전과 비교할 때 쓴다 |
| `--attempts 2` | 출력 검사(자기 이름·어미 섞임·반복 등)에 걸리면 곁들일 거리를 바꿔 다시 만드는 횟수(처음 포함). 게임과 같은 기본 2. 1 이면 다시 만들지 않는다 |
| `--system-in-user auto\|on\|off` | 시스템 메시지를 사용자 메시지 앞에 붙여 보낸다. 기본 auto 는 LM Studio 에서 모델마다 시스템 메시지가 빠지는지 입력 토큰 수로 보고 빠질 때만 붙인다 |
| `--host` | 서버 주소를 바꿀 때. 기본은 `http://127.0.0.1:1234`(LM Studio), `http://127.0.0.1:11434`(Ollama). `localhost` 는 Windows 에서 요청마다 약 2초 늦다 |

## 비교하는 방식

| 방식 | 내용 | 결과로 정할 것 |
|---|---|---|
| `single` | 한 번 호출. 상황은 키-값, 예시 대사와 대화 기억 포함 | 기준선 |
| `facts_sentence` | 상황을 문장으로 | 요청의 Facts를 키-값으로 둘지 문장으로 둘지 |
| `no_examples` | 예시 대사를 뺌 | 페르소나 정의서에 예시가 필요한지 |
| `no_memory` | 대화 기억을 뺌 | Memory 필드가 필요한지 |
| `two_step` | 행동 선택과 대사 생성을 두 번에 나눔 | 생성기 안에서 한 번에 할지 나눌지 |
