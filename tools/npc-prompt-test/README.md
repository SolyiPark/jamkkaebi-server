# 도깨비 프롬프트 시험기

입출력 계약을 확정하기 전에, 실제 모델이 도깨비 반응을 쓸 만하게 만드는지 PC에서 확인하는 스크립트다.
장면마다 프롬프트를 만들어 로컬 모델(LM Studio)에 넣고, 자동 검사 결과를 CSV로 저장한다.
말투와 상황 반영 점수는 사람이 CSV에 직접 매긴다. Python 3.10 이상, 표준 라이브러리만 쓴다.

장면과 행동은 [터치 상호작용 기획안](../../docs/npc-touch-interaction-design.pdf)을 따른다.

- 주인이 NPC를 탭하면 포커스 줌 뒤 짧게 인사하고, 선택지(안부 묻기 · 관리하기 · 이야기 듣기)로 교류한다. 주인은 NPC를 끌어당겨 옮길 수도 있다.
- 손님은 도깨비를 건드릴 수 없고 전시관(건물·도깨비 배치)을 관람만 한다. 손님이 보는 동안 도깨비는 짧은 말풍선을 띄운 채 걸어 다닌다.
- 주인은 언제든 관리(재플레이)할 수 있어서 "조건 미충족" 상황은 없다.
- 행동은 4개 애니메이션(Idle · Walking · Positive · Struggle) 중 하나로 표현한다.
  - Talk는 아트의 w자 입 모양을 살리기 어려워 뺐다. 말하는 행동은 Idle에 말풍선으로 표현한다.
  - Struggle(버둥거림)은 NPC를 끌어당길 때 쓴다.
  - Walking은 손님 관람 중 말풍선을 띄우고 걸을 때 쓴다.
  - Negative는 거절할 상황이 없어 뺐다. 불편함은 대사로 드러낸다.
- 놀람 · 수줍음 · 서운함 같은 세부 감정은 대사로 드러낸다.
- 지난 일은 저장된 이력이 있을 때만, 문화재 사실은 검수된 데이터(서버 시드의 `realStory`)로만 말한다.
- 대화의 목적은 플레이어가 상호작용을 통해 도깨비에게 **정이 들게 하는 것**이다. 무뚝뚝하거나 장난스러운 성격도 상대를 밀어내거나 깎아내리지 않는다. 욕설과 지나친 퉁명스러움은 공통 금칙어(`data/forbidden.json`)로 거른다.
- 도깨비마다 실화 이야기가 3개씩 있다(`personas.json` 의 `stories`). 이야기 듣기 때마다 게임이 돌려 가며 하나를 주어, 3개를 다 들려줄 때까지 같은 이야기를 반복하지 않는다.

## LM Studio로 돌리기

1. **모델 받기**: Discover 탭에서 모델을 검색해 내려받는다. 모바일에 올릴 크기를 보려면 GGUF의 Q4_K_M 양자화를 고른다. 모델마다 라이선스를 확인한다.
2. **서버 켜기**: Developer 탭에서 서버를 켠다(기본 포트 1234).
   - 설정에서 Just-in-Time 모델 로딩을 켜 두면 스크립트가 부를 때 모델이 자동으로 올라온다. 끄면 시험할 모델을 미리 로드해 둔다.
   - 메모리가 부족하면 다른 모델을 내리고 한 번에 하나씩 돌린다.
   - 새 모델이 로드되지 않으면 설정에서 llama.cpp 런타임을 최신으로 올린다.
3. **모델 이름 확인**:

   ```bash
   python run.py --backend lmstudio --list-models
   ```

4. **돌리기**: 목록에 나온 이름을 그대로 쓴다. (3번 반복)

   ```bash
   python run.py --backend lmstudio --models <모델이름> --variants single,two_step --repeat 3
   ```

   - 생각 모드는 기본적으로 끈다(`reasoning_effort: none`). 켜 두면 Gemma 4처럼 출력 한도를 생각에 다 쓰고 대사를 비워 돌려줄 수 있다. 비교하려면 `--allow-think` 를 붙인다.
   - LM Studio는 생성 시간을 따로 알려 주지 않아 초당토큰은 전체 응답 시간으로 어림한 값이다.


## 프롬프트만 보기

모델 없이 프롬프트가 어떻게 만들어지는지 본다. LM Studio 채팅 창에 붙여 넣어 손으로 시험할 때도 쓴다.

```bash
python run.py --dry-run --variants single --scenes S05
```

## 옵션

| 옵션 | 뜻 |
|---|---|
| `--backend lmstudio` | LM Studio로 보낸다 |
| `--list-models` | 서버에서 쓸 수 있는 모델 이름을 보여 주고 끝낸다 |
| `--variants` | 돌릴 방식(아래 표). 기본은 전부 |
| `--scenes S01,S05` | 일부 장면만 |
| `--repeat N` | 장면마다 N번 반복. 행동 성향을 보려면 3 이상 |
| `--no-format` | JSON 스키마 형식 제약을 끈다. 켜고 끈 결과를 비교할 때 쓴다 |
| `--think-off` | Ollama에서 생각 모드를 끈다 (qwen3 등). LM Studio는 기본으로 끈다 |
| `--allow-think` | LM Studio에서 생각 모드를 허용한다. 비교용 |
| `--seed N` | 결과를 재현하고 싶을 때 |
| `--line-chars 30` / `--max-chars 40` | 프롬프트에 적는 대사 길이 / 길이OK 판정 기준. 장면에 `lineChars` · `maxChars` 가 있으면 그 값을 쓴다 |
| `--host` | 서버 주소를 바꿀 때. 기본은 LM Studio 1234, Ollama 11434 포트 |

## 비교하는 방식

| 방식 | 내용 | 결과로 정할 것 |
|---|---|---|
| `single` | 한 번 호출. 상황은 키-값, 예시 대사와 대화 기억 포함 | 기준선 |
| `facts_sentence` | 상황을 문장으로 | 요청의 Facts를 키-값으로 둘지 문장으로 둘지 |
| `no_examples` | 예시 대사를 뺌 | 페르소나 정의서에 예시가 필요한지 |
| `no_memory` | 대화 기억을 뺌 | Memory 필드가 필요한지 |
| `two_step` | 행동 선택과 대사 생성을 두 번에 나눔 | 생성기 안에서 한 번에 할지 나눌지 |

## 장면 구성

18개 장면은 짝을 지어 비교하도록 짰다. 짝끼리 결과가 달라야 페르소나와 상황이 반영된 것이다.
번호는 예전 결과와 맞추려고 그대로 두었다. 
| 무엇을 보나 | 장면 | 같은 것 | 다른 것 |
|---|---|---|---|
| 말투 | S01 ↔ S02 | 주인 탭 인사 (행동 하나뿐) | 말발굽 하오체 / 묘작이 반말·의성어 |
| 상태에 따른 대사 | S03 ↔ S04 | 구름결, 주인 안부 묻기 (행동은 안부 답하기 하나) | 흐려짐 → 관리 부탁 / 선명 + 이틀 전 관리 → 이력 떠올리기. 필수어포함으로 본다 |
| 손님 관람 | S05 ↔ S06 | 향산이, 걸으며 짧은 말풍선(Walking) | 첫 손님 → 지난 만남을 지어내지 않음 / 4번째 손님 → 알아보기 |
| 같은 돌봄 다른 성격 | S07 · S08 · S09 | 관리 완료 | 밤바다 담담 / 묘작이 기쁨 / 향산이 오랜 방치에도 느긋한 반가움 |
| 실화 이야기 | S10 · S11 · S18 · S19 · S20 | 주인 이야기 듣기, 실화 한 문장 | 다섯 도깨비의 말투로 사실을 바꾸지 않고 풀어내는지. 필수어포함으로 사실 키워드를 본다 |
| 지난 이야기와 다른 이야기 | S10 · S19 | 대화 기억에 지난번 들려준 이야기가 있음 | 지난 이야기(S10 암행어사 / S19 옻칠 자개)를 다시 풀지 않고 이번 실화만 들려주는지. 사람이 읽고 확인한다 |
| 대화 기억 | S14 | 밤바다, 주인 안부 묻기 (행동은 지난 대화 꺼내기) | 지난 대화를 꺼내되 그대로 반복하지 않고, 주인에게 시키지 않음 |
| 끌어당기기 | S15 · S16 · S17 | 주인이 끌어당김, 버둥거림(Struggle) | 묘작이 놀이처럼 즐김 / 밤바다 투덜대도 밀어내지 않고 살살 다뤄 달라 함 / 구름결 깨질까 수줍게 조심해 달라 함. '놔'·'놓아'·'손대지 마'는 공통 금칙어로 잡는다 |

손님 장면(S05, S06)에는 선명도를 넣지 않는다.
